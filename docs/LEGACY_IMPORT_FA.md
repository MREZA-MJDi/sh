# راهنمای انتقال اطلاعات از Sheykhan قدیمی به SH

این انتقال عمداً به‌صورت فرمان مستقل، تکرارپذیر و Dry-run-first پیاده‌سازی شده است. هیچ Migration دیتابیس، نقش یا حسابی را تغییر نمی‌دهد و هیچ‌وقت دیتابیس قدیمی را نمی‌نویسد.

## پیش‌نیازها

1. از دیتابیس قدیمی و فایل‌های رسانه‌ای نسخه پشتیبان کامل بگیرید.
2. یک کاربر MySQL فقط‌خواندنی برای دیتابیس قبلی بسازید؛ این حساب نباید مجوز `INSERT`، `UPDATE`، `DELETE` یا DDL داشته باشد.
3. مقادیر اتصال را فقط روی محیط مقصد در `.env` قرار دهید:

```dotenv
LEGACY_DB_HOST=127.0.0.1
LEGACY_DB_PORT=3306
LEGACY_DB_DATABASE=sheykhan
LEGACY_DB_USERNAME=legacy_reader
LEGACY_DB_PASSWORD=...
LEGACY_DB_SOCKET=
LEGACY_DB_PREFIX=
```

4. Migrationهای مقصد و `RolePermissionSeeder` باید اجرا شده باشند.
5. شناسه آموزشگاه قدیمی را از دیتابیس قدیمی مشخص کنید؛ واردکردن بدون تعیین academy ID مجاز نیست.

## مرحله اول: گزارش بدون تغییر داده

```bash
php artisan migrate --force
php artisan db:seed --class=RolePermissionSeeder --force
php artisan sh:import-legacy-academy --connection=legacy --legacy-academy-id=54
```

این اجرا فقط SELECT روی دیتابیس منبع انجام می‌دهد و تعداد حساب‌ها، دوره‌ها، کلاس‌ها، ارتباط‌های ولی/دانش‌آموز، عضویت‌های کلاس و ثبت‌نام‌ها را گزارش می‌کند. تعارض ایمیل/موبایل باعث توقف می‌شود؛ هیچ حسابی بر اساس تشابه نام یا موبایل به حساب موجود متصل نمی‌شود.

## مرحله دوم: اعمال انتقال

فقط پس از بازبینی گزارش، رفع تعارض‌ها و گرفتن نسخه پشتیبان تازه:

```bash
php artisan sh:import-legacy-academy --connection=legacy --legacy-academy-id=54 --apply
```

فرمان برای هر موجودیت نگاشت `legacy_import_maps` ایجاد می‌کند؛ اجرای دوباره همان انتقال، حساب/دوره/کلاس/ثبت‌نام تکراری نمی‌سازد.

## داده‌هایی که منتقل می‌شوند

- حساب‌های دارای نقش شناخته‌شده `student`، `parent`، `teacher` یا `admin` در محدوده آموزشگاه انتخاب‌شده.
- ارتباط ولی و دانش‌آموز از `parent_student`.
- دوره‌ها و مدرس اصلی انتخاب‌شده از `course_teacher`.
- کلاس‌ها و مدرس قابل‌انتساب از `classroom_teacher`.
- اعضای فعال کلاس از `classroom_student`.
- ثبت‌نام‌های دوره از `course_enrollments`.

مالک آموزشگاه قدیمی و نقش‌های اختصاصی قدیمی که معادل امنی در چهار نقش مقصد ندارند، خودکار به مدیر سامانه تبدیل نمی‌شوند. باید برای آن‌ها نقش/مجوز مقصد جداگانه طراحی و به‌صورت موردی نگاشت شوند.

## پرداخت‌های تاریخی و دسترسی

برای دوره رایگان، ثبت‌نام فعال قدیمی به ثبت‌نام فعال مقصد تبدیل می‌شود. برای دوره پولی، دسترسی فقط وقتی فعال می‌شود که وضعیت پرداخت قدیمی `paid` باشد، مبلغ پرداختی حداقل قیمت ثبت‌شده را پوشش دهد و تراکنش مالی با وضعیت `completed` در منبع وجود داشته باشد. موارد دیگر با وضعیت `pending_payment` وارد می‌شوند تا دسترسی محافظت‌شده بدون مدرک پرداخت آزاد نشود.

## گذرواژه‌ها

هش‌های استاندارد bcrypt و قالب‌های قدیمی WordPress phpass / wrapped bcrypt حفظ می‌شوند. نخستین ورود موفق با ایمیل یا موبایل، هش legacy را به هش فعلی Laravel تبدیل می‌کند. اگر قالب هش ناشناخته باشد، Dry-run متوقف می‌شود؛ گذرواژه‌های کاربران بازنشانی یا حدس زده نمی‌شوند.

## موارد خارج از این فرمان

رسانه‌ها، فایل‌های تکلیف، ویدیوهای ضبط‌شده، فایل‌های SpotPlayer و Quiz24، تاریخچه حضور و غیاب، آزمون‌های قبلی، نمرات، پیام‌ها و تنظیمات سایت در این مرحله منتقل نمی‌شوند. برای آن‌ها به نگاشت جداگانه و بررسی فایل‌ها/شناسه‌های خارجی نیاز است. پس از اجرای Dry-run می‌توان گزارش تعداد و ساختار این داده‌ها را برای فاز دوم تهیه کرد.

**نکته:** این فرمان در این شاخه آماده شده، اما تا دریافت اتصال/خروجی واقعی دیتابیس قدیمی Dry-run واقعی اجرا نشده و هیچ اطلاعات production جابه‌جا نشده است.
