# احراز هویت و داشبوردهای نقش‌محور

## ورود و ثبت‌نام

- مسیر ورود همه نقش‌ها: `/login`
- مسیر ثبت‌نام عمومی: `/register`
- ثبت‌نام عمومی فقط حساب دانش‌آموز می‌سازد؛ مقدار role ارسالی از مرورگر پذیرفته نمی‌شود.
- مقصد ورود بر اساس نقش ذخیره‌شده در دیتابیس تعیین می‌شود: مدیر، مدرس، دانش‌آموز یا ولی.
- گذرواژه با cast هش‌شده مدل User ذخیره می‌شود؛ فرم‌ها CSRF دارند و مسیرهای ورود/ثبت‌نام محدودیت درخواست دارند.
- تأیید ایمیل در این نسخه فعال نیست؛ فعال‌سازی آن به تنظیم و تأیید واقعی سرویس ایمیل نیاز دارد.

## حساب‌های آزمایشی فقط برای محیط توسعه

در فایل .env محلی:

```dotenv
SHIKHAN_DEMO_ACCOUNTS=true
SHIKHAN_DEMO_PASSWORD=ShikhanDemo@2026!
```

سپس:

```bash
php artisan migrate --seed
```

هر چهار حساب از یک گذرواژه محلی مشترک استفاده می‌کنند:

| نقش | ایمیل |
|---|---|
| مدیر | admin@sh.local |
| مدرس | teacher@sh.local |
| دانش‌آموز | student@sh.local |
| ولی | parent@sh.local |

این Seeder فقط در محیط‌های local و testing اجرا می‌شود. در production حتی با روشن بودن فلگ نیز حساب آزمایشی ساخته نمی‌شود. این حساب‌ها داده آموزشی نمونه تولید نمی‌کنند؛ داشبوردها در نبود رکورد واقعی، empty state معتبر نشان می‌دهند.

## مجوزها و منو

- مجوزهای تعریف‌شده در RolePermissionSeeder منبع دسترسی UI و route middleware هستند.
- منوی هر نقش فقط آیتم‌هایی را نشان می‌دهد که همان نقش مجوزشان را دارد.
- منوی مدرس به سکشن‌های داشبورد محدود به کلاس‌های تخصیص‌یافته لینک می‌شود؛ پیوندی به مدیریت کاربران، تنظیمات یا سرویس‌های خارجی ندارد.
- مخفی بودن لینک جایگزین middleware نیست؛ دسترسی مستقیم به routeهای نقش دیگر همچنان با پاسخ 403 بسته است.
- داشبورد دانش‌آموز از رابطه کلاس‌های متصل به همان کاربر داده می‌خواند و نمرات، حضور و غیاب و تکالیف را به شناسه همان دانش‌آموز محدود می‌کند.

## مسیرهای داشبورد

- مدیر: `/admin`
- مدرس: `/teacher`
- دانش‌آموز: `/student`
- ولی: `/parent`
