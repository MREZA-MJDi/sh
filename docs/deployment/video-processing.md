# پردازش و آپلود ویدئو

آپلود ویدئو به‌صورت بخش‌بخش انجام می‌شود. هر بخش جداگانه در فضای خصوصی ذخیره می‌شود و در صورت قطع اینترنت، مرورگر می‌تواند بخش‌های سالم را دوباره استفاده کند. پس از دریافت همه بخش‌ها، درخواست کاربر فقط کار نهایی‌سازی را در صف Redis ثبت می‌کند؛ اتصال بخش‌ها و ساخت فایل نهایی داخل Worker انجام می‌شود.

## پیش‌نیاز سرور

- نصب ffmpeg و ffprobe و در دسترس بودن آن‌ها در PATH کاربر اجرای Worker.
- نصب و فعال بودن Redis و افزونه PHP phpredis.
- فعال بودن ماندگاری Redis (AOF یا snapshot) و تنظیم حافظه مناسب؛ Redis نباید با سیاست حذف کلیدهای صف اجرا شود.
- فضای موقت کافی روی دیسک خصوصی local برای فایل اصلی، بخش‌های آپلود و فایل پردازش‌شده.
- ساخت symlink عمومی Laravel با دستور php artisan storage:link برای خروجی عمومی تیزر.

## صف‌ها و Workerها

صف عمومی برنامه از اتصال پیش‌فرض Redis استفاده می‌کند. نهایی‌سازی آپلود و پردازش سنگین ویدئو دو صف جدا دارند؛ هر دو روی Redis هستند، اما Workerهای مستقل دارند تا تبدیل طولانی ویدئو جلوی تکمیل آپلودهای تازه را نگیرد.

Worker عمومی: php artisan queue:work redis --queue=default --sleep=2 --tries=3 --timeout=120

Worker نهایی‌سازی آپلود: php artisan queue:work upload-finalization --queue=upload-finalize --sleep=1 --tries=3 --timeout=900

Worker پردازش ویدئو: php artisan queue:work video --queue=video --sleep=3 --tries=3 --timeout=3600

Workerها باید با Supervisor یا systemd دائماً فعال باشند و بعد از هر انتشار نسخه، restart شوند. زمان‌بندی Laravel نیز باید فعال باشد تا نشست‌های منقضی‌شده و بخش‌های باقی‌مانده پاک‌سازی شوند؛ cron استاندارد php artisan schedule:run باید هر دقیقه اجرا شود.

## روند آپلود

1. سرور برای فایل یک شناسه و اندازه بخش‌ها تعیین می‌کند.
2. مرورگر فایل را بخش‌بخش می‌فرستد و هر بخش با شناسه مستقل ذخیره می‌شود.
3. اگر ارتباط قطع شود، ادامه آپلود فقط بخش‌های ناقص را دوباره می‌فرستد.
4. بعد از دریافت کامل، سرور یک کار در صف Redis ثبت می‌کند و سریع به مرورگر پاسخ می‌دهد.
5. Worker بخش‌ها را به فایل نهایی تبدیل می‌کند، اندازه را کنترل می‌کند و سپس رکورد ویدئو را ثبت می‌کند.
6. پس از آن، پردازش ویدئو با FFmpeg در صف انجام می‌شود. خروجی ابتدا با نام موقت ساخته می‌شود، سپس FFprobe وجود stream تصویری، ابعاد و مدت معتبر را بررسی می‌کند؛ فقط پس از تأیید، فایل با rename اتمیک منتشر و مسیر دیتابیس به آن تغییر می‌کند. فایل اصلی تا آن لحظه در فضای خصوصی حفظ می‌شود.

بخش‌های آپلود تا ثبت موفق فایل نهایی حفظ می‌شوند. خطای موقت صف یا خاموش‌شدن Worker نباید باعث حذف بخش‌های سالم شود. فایل پردازش‌شده ناقص یا فاقد stream تصویری هرگز به‌عنوان ویدیوی آماده ثبت نمی‌شود. در صورت تمام‌شدن تلاش‌های مجدد، نشست با وضعیت ناموفق مشخص می‌شود و فایل ناقص به‌عنوان ویدئوی آماده نمایش داده نمی‌شود.

## محدودیت‌ها و وضعیت فعلی

- سقف تیزر در config/learning.php با max_teaser_mb و سقف ویدئوی کلاس با max_lesson_mb کنترل می‌شود.
- اندازه بخش‌ها با LEARNING_CHUNK_MB تنظیم می‌شود و سرور آن را با محدودیت PHP هماهنگ می‌کند.
- زمان اعتبار هر نشست با LEARNING_UPLOAD_SESSION_TTL_HOURS تعیین می‌شود.
- آپلود چندبخشی فعلی برای تیزر و ویدئوی ضبط‌شده کلاس/SpotPlayer فعال است. مسیر مستقل MediaAsset هنوز به ویرایشگر محتوای درس متصل نشده است.
