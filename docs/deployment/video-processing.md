# پردازش و آپلود ویدئو

آپلود ویدئو به‌صورت بخش‌بخش انجام می‌شود. هر بخش جداگانه در فضای خصوصی ذخیره می‌شود و در صورت قطع اینترنت، مرورگر می‌تواند بخش‌های سالم را دوباره استفاده کند. پس از دریافت همه بخش‌ها، درخواست کاربر فقط کار نهایی‌سازی را در صف Redis ثبت می‌کند؛ اتصال بخش‌ها و ساخت فایل نهایی داخل Worker انجام می‌شود.

## پیش‌نیاز سرور

- نصب ffmpeg و ffprobe و در دسترس بودن آن‌ها در PATH کاربر اجرای Worker.
- برای ساخت ویدیوی واترمارک‌دار، نسخه FFmpeg باید فیلتر `drawtext` و یک قلم پیش‌فرض قابل خواندن برای Worker داشته باشد.
- نصب و فعال بودن Redis و افزونه PHP phpredis.
- فعال بودن ماندگاری Redis (AOF یا snapshot) و تنظیم حافظه مناسب؛ Redis نباید با سیاست حذف کلیدهای صف اجرا شود.
- فضای موقت کافی روی دیسک خصوصی local برای فایل اصلی، بخش‌های آپلود و فایل پردازش‌شده.
- از `php artisan storage:link` برای پوستر تریلر و سایر تصاویر عمومی استفاده کنید. فایل ویدیو در فضای خصوصی نگهداری می‌شود.
- هنگام انتشار این تغییر، پس از به‌روزرسانی کد و راه‌اندازی مجدد worker ویدیو، `php artisan learning:privatize-teasers` را اجرا کنید. این فرمان نسخه خصوصی تریلرهای قبلی را بررسی می‌کند و سپس نسخه عمومی را حذف می‌کند. قواعد وب‌سرور مربوط به آدرس قدیمی تریلر را اعمال کنید و نسخه‌های آن آدرس را از کش CDN پاک کنید.

## صف‌ها و Workerها

صف عمومی برنامه از اتصال پیش‌فرض Redis استفاده می‌کند. نهایی‌سازی آپلود و پردازش سنگین ویدئو دو صف جدا دارند؛ هر دو روی Redis هستند، اما Workerهای مستقل دارند تا تبدیل طولانی ویدئو جلوی تکمیل آپلودهای تازه را نگیرد.

Worker عمومی: php artisan queue:work redis --queue=default --sleep=2 --tries=3 --timeout=120

Worker نهایی‌سازی آپلود: php artisan queue:work upload-finalization --queue=upload-finalize --sleep=1 --tries=3 --timeout=900

Worker پردازش ویدئو: php artisan queue:work video --queue=video --sleep=3 --tries=3 --timeout=3600

Workerها باید با Supervisor یا systemd دائماً فعال باشند و بعد از هر انتشار نسخه، restart شوند. زمان‌بندی Laravel نیز باید فعال باشد تا نشست‌های منقضی‌شده و بخش‌های باقی‌مانده پاک‌سازی شوند؛ cron استاندارد php artisan schedule:run باید هر دقیقه اجرا شود.

اولین درخواست پخش تریلر یا ویدیوی داخلی، نسخهٔ واترمارک‌دار همان حساب را در صف ویدیو می‌سازد. پلیر تا آماده‌شدن آن منتظر می‌ماند. نسخه در دیسک خصوصی نگه‌داری می‌شود و زمان‌بند فایل‌های قدیمی‌تر از دو روز را پاک می‌کند. ارسال ویدیوی دانش‌آموز از PHP انجام می‌شود تا مسیر Nginx مربوط به فایل مبدأ استفاده نشود.

## روند آپلود

1. سرور برای فایل یک شناسه و اندازه بخش‌ها تعیین می‌کند.
2. مرورگر فایل را بخش‌بخش می‌فرستد و هر بخش با شناسه مستقل ذخیره می‌شود.
3. اگر ارتباط قطع شود، ادامه آپلود فقط بخش‌های ناقص را دوباره می‌فرستد.
4. بعد از دریافت کامل، سرور یک کار در صف Redis ثبت می‌کند و سریع به مرورگر پاسخ می‌دهد.
5. Worker بخش‌ها را به فایل نهایی تبدیل می‌کند، اندازه را کنترل می‌کند و سپس رکورد ویدئو را ثبت می‌کند.
6. پس از آن LocalVideoProcessor ابتدا ورودی را با FFprobe بررسی می‌کند. فایل سازگار H.264/yuv420p با صدای AAC-LC یا بدون صدا، ابعاد مجاز و پروفایل سازگار با مرورگر، با Stream Copy داخل MP4 قرار می‌گیرد؛ در صورت ناسازگاری، FFmpeg آن را Encode می‌کند. خروجی ابتدا با نام موقت ساخته می‌شود، سپس FFprobe وجود stream تصویری، ابعاد و مدت معتبر را بررسی می‌کند؛ فقط پس از تأیید، فایل با rename اتمیک منتشر و مسیر دیتابیس به آن تغییر می‌کند. فایل اصلی تا آن لحظه در فضای خصوصی حفظ می‌شود.

بخش‌های آپلود تا ثبت موفق فایل نهایی حفظ می‌شوند. خطای موقت صف یا خاموش‌شدن Worker نباید باعث حذف بخش‌های سالم شود. فایل پردازش‌شده ناقص یا فاقد stream تصویری هرگز به‌عنوان ویدیوی آماده ثبت نمی‌شود. در صورت تمام‌شدن تلاش‌های مجدد، نشست با وضعیت ناموفق مشخص می‌شود و فایل ناقص به‌عنوان ویدئوی آماده نمایش داده نمی‌شود.

## محدودیت‌ها و وضعیت فعلی

- سقف تیزر در config/learning.php با max_teaser_mb و سقف ویدئوی کلاس با max_lesson_mb کنترل می‌شود.
- اندازه بخش‌ها با LEARNING_CHUNK_MB تنظیم می‌شود و سرور آن را با محدودیت PHP هماهنگ می‌کند.
- زمان اعتبار هر نشست با LEARNING_UPLOAD_SESSION_TTL_HOURS تعیین می‌شود.
- آپلود چندبخشی فعلی برای تیزر و ویدئوی ضبط‌شده کلاس/SpotPlayer فعال است. مسیر مستقل MediaAsset هنوز به ویرایشگر محتوای درس متصل نشده است.

## جداسازی فایل محلی و SpotPlayer

- تریلر و ویدیوی محلی توسط LocalVideoProcessor آماده می‌شوند. تریلر صفحه دوره پس از ورود به حساب کاربری پخش می‌شود.
- ویدیوی موجود در SpotPlayer صرفاً با شناسه خارجی ثبت می‌شود. ارسال فایل همراه شناسه در فرم‌های جدید مجاز نیست.
- فایل‌های قدیمی که شناسه خارجی دارند حذف نمی‌شوند و برای اتصال رسمی در وضعیت waiting_contract باقی می‌مانند؛ Encode مجدد محلی انجام نمی‌شود.
- رایگان یا پولی بودن دوره، جایگزین تصمیم درباره منبع پخش نیست. دسترسی دوره و عضویت کلاس همچنان در Laravel کنترل می‌شود. هیچ دوره قدیمی به‌صورت خودکار منتقل نمی‌شود.
- API Key و لایسنس در Backend مدیریت می‌شوند. تا دریافت قرارداد معتبر، Gateway غیرواقعی باقی می‌ماند؛ کلید یا لینک پخش ساخته نمی‌شود.

## ارسال فایل خصوصی توسط Nginx (اختیاری)

بلوک internal در deploy/nginx-learning.conf را با مسیر واقعی پروژه، داخل server مربوط به همان سایت نصب کنید. پس از nginx -t و reload، دسترسی مستقیم به /_protected_course_video/ باید 404 بدهد. سپس LEARNING_NGINX_PRIVATE_VIDEO=true را در .env تنظیم و config cache را بازسازی کنید. درخواست عضو باید با HTTP Range پاسخ 206 بگیرد و غیرعضو 404. در نبود این تنظیم، مسیر قبلی PHP بدون تغییر فعال است.

برای VPS کوچک LEARNING_VIDEO_THREADS=1 و یک Video Worker توصیه می‌شود. FFmpeg فقط در صورت ناسازگاری فایل Encode انجام می‌دهد؛ Remux به‌معنی کاهش قطعی حجم فایل نیست.
